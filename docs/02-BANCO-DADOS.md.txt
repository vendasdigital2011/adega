# PDR-003 — Banco de Dados

## Projeto

**Nome:** Adega Cloud

**Documento:** PDR-003 — Banco de Dados

**Versão:** 1.0

---

# Objetivo

Definir toda a estrutura do banco de dados do Adega Cloud, garantindo organização, integridade, desempenho e escalabilidade.

O banco deverá ser preparado para crescimento futuro, incluindo suporte a múltiplas empresas (multi-tenant), auditoria e integrações.

---

# Banco de Dados

Tecnologia:

- PostgreSQL (Supabase)

Características obrigatórias:

- UUID como chave primária
- Foreign Keys
- Índices
- Constraints
- Soft Delete quando necessário
- Auditoria
- Row Level Security (RLS)

---

- barcode
- sku

- customer_id
- supplier_id
- sale_date
- purchase_date
- due_date
- created_at
- company_id

---

# Integridade

Obrigatório utilizar:

- Foreign Keys
- Cascade quando apropriado
- Restrict quando necessário
- Unique para SKU
- Unique para Barcode
- Check Constraints para valores monetários
- Valores padrão para status

---

# Segurança

Todas as tabelas deverão utilizar:

- Row Level Security (RLS)
- Policies por empresa
- Policies por usuário
- Policies por perfil

Nenhum usuário poderá acessar dados de outra empresa.

---

# Auditoria

Registrar automaticamente:

- Inclusões
- Alterações
- Exclusões
- Login
- Logout
- Cancelamentos
- Alterações financeiras
- Movimentações de estoque

---

# Escalabilidade

O banco deverá suportar futuramente:

- Multiempresa
- Multiunidade
- Múltiplos caixas
- Múltiplos depósitos
- API pública
- Aplicativo móvel
- Integrações fiscais
- Inteligência Artificial

Sem necessidade de remodelagem estrutural.

---

# Critérios de Aceite

O banco será considerado aprovado quando:

- Todas as tabelas estiverem modeladas.
- Relacionamentos definidos.
- Índices documentados.
- Constraints especificadas.
- Estratégia de segurança definida.
- Estrutura preparada para evolução do sistema.
